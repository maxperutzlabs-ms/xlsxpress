# XlsxPress design

This document records the design decisions of XlsxPress, ideas for later, how we test and how we work on the project. Keep it up to date when a decision changes.

XlsxPress converts text and Parquet files to Excel workbooks without changing their values. It is installed with `uv tool install xlsxpress` (or pip), has a CLI, and adds Windows right-click entries ("Open in Excel", conversion dialog). Polars reads the files, our own xlsxwriter code writes the workbook.

## Decisions

| Topic | Decision | Notes |
|---|---|---|
| Excel writer | Own xlsxwriter code, `constant_memory` mode | Full control per data type; no surprises from polars' Excel defaults (e.g. its old 3-decimal default). Rows are streamed, so memory use stays flat for large files (measured with polars' own writer: 740 MB → 131 MB and 12.1 s → 8.4 s for 100k × 20 cells). |
| Strings | Always written as text | `strings_to_formulas`, `strings_to_urls` and `strings_to_numbers` are off. `=1+1` stays text. |
| Integers > 15 digits | Written as numbers, like Excel itself | Excel keeps only 15 significant digits and replaces the rest with zeros. Documented as a limitation. Keep the writer's type mapping flexible, so this can later become text or an option. |
| Floats | Numbers in Excel's `General` format, at most 16 significant digits | xlsxwriter writes numbers with 16 significant digits; Excel shows 15. A value that needs 17 digits for an exact round trip can differ in its last binary digit (relative difference below 1e-15), e.g. `0.1 + 0.2` is written as `0.3`. Float32 values are converted through their shortest decimal text, so `0.1` stays `0.1`. Decimals are written as numbers. |
| `inf`, `-inf` | Text `inf`, `-inf` | Excel has no infinity value. |
| `NaN`, null | Blank cell | |
| Booleans | Excel booleans (`TRUE`, `FALSE`) | |
| Dates and datetimes (Parquet) | Excel dates with a date or datetime format | Parquet types are explicit, not guessed, so this is safe and keeps sorting and date calculations working. Format `yyyy-mm-dd`, `yyyy-mm-dd hh:mm:ss`, or with `.000` when a column has fractional seconds. Excel's resolution is 1 ms; finer precision is lost. Dates before 1900-03-01 are written as ISO 8601 text, because Excel's 1900 leap year bug makes earlier serial dates unreliable. Documented. Text files are never parsed as dates. |
| Timezone-aware datetimes | Text in ISO 8601 with offset, e.g. `2024-01-02T10:00:00+01:00` | Documented; Excel has no timezones. Converted by polars, which needs no `tzdata` package on Windows. |
| Time, duration, list, struct, binary columns | Text | Time as ISO 8601 (`10:30:05`), duration like `1 day, 0:00:05`, lists and structs like `[1, 2]` and `{'a': 1}`, binary as hexadecimal. |
| Header formatting | Bold, wrapped, frozen first row, plain autofilter | No Excel Table. `--plain` turns all of this off. Column names are always written as text, and empty names stay empty. |
| Column widths | Estimated from header and first 1,000 rows, between 40 and 125 pixels | Date columns are always wide enough for the full date, because Excel shows `###` for a date that doesn't fit. |
| Excel limits | Too many rows or columns: `ExcelLimitError` before writing, no file is created. Strings > 32,767 characters: truncated with a `ConversionWarning`. | |
| Reading text files: types | Every column is read as text first. It becomes integers if every value is a plain integer (`-12`), floats if every value is a plain integer or decimal (`1.5`, `.5`, `1.5e-3`, `1e+05`) or infinity (`inf`, `-Infinity`, any case). Otherwise the whole column stays text. | Keeps leading zeros (`007`), `+5`, spaces, decimal commas, dates, `TRUE`/`FALSE`, gene names and IDs like `2310009E13` unchanged. An integer mantissa needs a signed exponent (`1e+05` is a number, `1E5` is text); R and .NET write signed exponents. Trailing zeros are allowed (`1.10` becomes 1.1, the value is unchanged; Excel does the same). Integers beyond the 64-bit range become floats, consistent with the 15-digit decision. Making full-precision decimals text was rejected, as most pandas float columns would become text. |
| Reading text files: missing values | In an otherwise numeric column, `NA`, `NaN`, `nan`, `N/A`, `#N/A`, `null`, `NULL` and empty fields become blank cells | A column of only such tokens stays text. `-` and `--` are not missing values. No warning, since tools like MaxQuant write `NaN` everywhere. |
| Reading text files: encoding | UTF-8, UTF-16 or UTF-32 byte order mark decides; otherwise UTF-8. Not valid UTF-8: Windows-1252, then Latin-1, with a warning. NUL bytes without a byte order mark: error. Not valid text in the encoding of the byte order mark (e.g. cut-off UTF-16): error. | |
| Reading text files: format | Separator from the extension (`.tsv`) or sniffed from the first lines (`.csv`, `.txt`). The sniffer removes fully quoted fields (`"a,b"` between separators or line ends) before counting, so separators inside them don't count, while a quote inside a field (`5" cable`) is plain data. It prefers a separator with the same count on every line, then the most frequent on the header line. Standard `"` quoting; if that fails, read again without quote handling and warn if a name or value starts with a quote. The header row is checked first, because polars silently strips quotes from a header like `"5 inch" cable`. Repeated column names are renamed by polars (`a_duplicated_0`), with a warning. | Rows with more fields than the header, e.g. from comment lines at the top, give an error. Polars 2 no longer parses a quote inside an unquoted field with quote handling; the fallback warns only if a name or value starts with a quote, which gives the same result on polars 1.x and 2.x. |
| Output files | Next to the input file by default, named after it (`data.xlsx`). An existing file is never overwritten; a counter is added instead (`data-02.xlsx`). The workbook is first written to a work folder (`%LOCALAPPDATA%\xlsxpress\Cache\work`) and moved (temp folder) or copied (next to the input) to the output name only when complete, so a file under the output name is never unfinished, even if the process is killed. The output name is then reserved by creating the file exclusively, so parallel conversions never collide. A copy goes to `<output name>.part` in the output folder and replaces the reserved file with `os.replace` when complete; a process killed during the copy leaves the empty reserved file and the `.part` file, never a truncated workbook. | If a conversion fails, the reserved file and the work file are deleted again. A file that can't be read creates no output at all. Moved to the temp folder, which sits next to the work folder (same drive, same permissions), because a copy is a second new file that Windows Defender checks again when Excel opens it: measured +0.6 s for a 2.5 MB workbook. Copied next to the input, because a moved file keeps the permissions of the cache folder on Windows, and a move fails across drives (network shares). xlsxwriter's own temp files (the uncompressed rows) go to the work folder too. |
| Temp files | One temp folder for CLI, context menu and dialog: `platformdirs.user_cache_path("xlsxpress", appauthor=False) / "temp"`, e.g. `%LOCALAPPDATA%\xlsxpress\Cache\temp`. Names get a timestamp (`data_2026-11-06_142530.xlsx`), because Excel can't open two workbooks with the same name, even from different folders. Temp files are disposable, a quick way to look at a file in Excel, and open normally without a read-only prompt. | No read-only recommendation, because Excel asked about it on every "Open in Excel". To keep edits, save the workbook somewhere else. |
| Temp cleanup | Runs before each conversion to the temp folder, from the CLI too: deletes files older than `max_age_days` (14), then the oldest above `max_files` (100). The app config can override both. Age is the file's modification time. All `*.xlsx` files directly in the temp folder count, edited or not; Excel's lock files (`~$name.xlsx`), other files and subfolders are left alone. | Files that vanish or are locked (open in Excel) during cleanup are skipped. The README must say that temp files are deleted, edited or not. Before each conversion, files in the work folder older than one day are deleted too; they only exist when a conversion was killed, and the age limit protects conversions still running. |
| Conversion warnings | Collected by the pipeline and returned with the result (`ConversionResult.warnings`), message text only. The CLI prints `Warning: ...` to stderr; the context menu and the dialog show them in a message box. | |
| Conversion errors | Errors in reading and writing become one `ConversionError` with an actionable message, shown by both the CLI and the GUI. | The context menu shows the message in its error box; the log keeps the traceback. |
| Opening the written file fails | `OpenOutputError` (not a `ConversionError`) with the output path and the warnings. The message says the file was written and where, that it couldn't be opened, and that maybe no program is set up for `.xlsx` files. | The CLI prints the warnings and `Wrote <path>`, then `Error: ...`, and exits with 1, because the requested action failed. The context menu shows the warnings and the message in its boxes. |
| CLI | cyclopts. `xlsxpress.cli:main` returns the exit code: 0 for success, 1 for a conversion error (including a missing input file), 2 for invalid arguments. `Error: ...` and `Warning: ...` go to stderr as plain text, without color, and `Wrote <path>` to stdout. | Consistent with rawtrace-qc. |
| Install | uv tool (recommended), pip (supported). Updates and uninstall go through `uv tool upgrade` and `uv tool uninstall`. | `customtkinter` is a required dependency; there is no `gui` extra, so `uv tool install xlsxpress` gives the full feature set. |
| Context menu | HKCU `SystemFileAssociations`, command runs `pythonw.exe -m xlsxpress.app ...` from the install environment. Managed with `xlsxpress context-menu register | unregister | status`; on macOS and Linux these exit with an error. | `pythonw` avoids a console window; it is found next to `sys.executable`. Registering from an environment that isn't a uv tool install gives a warning, not an error, so a development venv can still register. A uv tool environment is recognised by its `uv-receipt.toml`, which works with any `UV_TOOL_DIR`. No menu icon. |
| Context menu entries | "Open in Excel (XlsxPress)" converts with the saved defaults and always opens the result, whatever the saved "Open in Excel after conversion" says; that option only sets the dialog's default. "Open conversion dialog (XlsxPress)" shows the dialog. | |
| Conversion dialog | The row limit field ("Convert only the first [N] rows", config key `preview`) is enabled only when its checkbox is checked. "Reset" sets the form to the built-in defaults without saving; "Save as default" saves. Without the row limit, an invalid value in its field is ignored when converting and keeps the saved value when saving; with it, the value must be a whole number greater than 0, otherwise nothing is converted or saved and the field gets a red border until it is valid. After a conversion that wrote a file, a banner shows the path, "Show in folder" and the warnings, the options are disabled and Convert turns into Close. It closes by itself only when the file was opened in Excel and there are no warnings. Errors are shown in full in the banner and logged with the traceback; Convert stays available. "About" is a modal window with the version, what "Save as default" and "Reset" do, the cleanup rules, and links to the temp folder and the config file. Colours, fonts and sizes live in `app/gui/theme.py`; the window uses light mode and explicit colours, so it looks the same in Windows dark mode. Buttons and checkboxes are reachable with Tab (customtkinter's are not by default). | Closing the window during a conversion cancels it (see "Progress and cancelling"). Converting again after a successful conversion was considered and rejected. The decisions live in `app/gui/dialog_logic.py` and are unit tested; the window in `app/gui/dialog.py` only reads widgets and shows outcomes. The worker thread hands its outcome to the Tk main thread through a queue polled with `after()`. |
| Progress and cancelling | A conversion from the context menu or the dialog that takes longer than 400 ms shows a small progress window (`app/gui/progress_window.py`): file name, elapsed time, the stage (reading, writing, saving, opening) and, while writing, the percentage of written rows. Closing it (or `Esc`) cancels the conversion without a message; in the dialog this returns to the form. Closing the dialog during a conversion cancels too. The window disappears at once, and the process ends when the conversion has stopped. A cancelled conversion leaves no file behind, also not in the work folder. The CLI shows no progress. | The pipeline and the writer take an optional `Progress` (`core/progress.py`) and raise `ConversionCancelled` (not a `ConversionError`) at the next check: between the stages and about every 10,000 cells while writing. Measured on a 132 MB TSV: reading 0.8 s, writing 44 s, cancel takes effect in about 0.1 s. Reading can't be interrupted, but is short. A cancel during the final move or copy lets it finish and then deletes the output. Ending the process instead was rejected: it leaves xlsxwriter's row file (uncompressed, larger than the input) in the work folder for a day. For the same reason a cancel deletes the row file directly instead of calling `workbook.close()`, which first builds the whole xlsx (5 s at 50% of that file); this uses xlsxwriter internals and is covered by a test. Errors and warnings of "Open in Excel" stay in message boxes. |
| Settings | `xlsxpress.config`: config file and log file, shared by CLI and app | Both live in `platformdirs.user_data_dir("xlsxpress", "perutzms")`, e.g. `%LOCALAPPDATA%\perutzms\xlsxpress`. The CLI doesn't import its settings from the app package. A config section that isn't a table, `true`, negative numbers and an `nrows` of 0 are rejected. |
| Python | `>= 3.12` | Matches rawtrace-qc. |
| Dependency bounds | `polars>=1.18`, `xlsxwriter>=3.2.1`, `customtkinter>=5.2.1`, `platformdirs>=2.1`, `cyclopts>=5.0` | Each is the oldest version that passes the test suite plus checks the suite misses: the dialog driven through a conversion (customtkinter 5.2.0 imports `distutils`, removed in Python 3.12), the real cache path (platformdirs 2.0 lacks `user_cache_path`) and the exit code for invalid arguments (cyclopts 4.x exits with 1). Polars below 1.18 lacks `pl.Int128`; 1.9 and older also fail real reader and writer tests. Recheck by installing the minimums with `uv pip install --resolution lowest-direct`. |
| CI | GitHub Actions like rawtrace-qc: lint job plus test matrix on Linux, Windows, macOS | Registry tests run on Windows only. They use an in-memory fake of `winreg` and never touch the real registry, except one round trip through it (`register`, `read_entries`, `unregister` below `Software\xlsxpress-tests`) that runs only with `XLSXPRESS_REGISTRY_TESTS=1`, which only the Windows CI job sets. |
| Release | Pushing a tag `vX.Y.Z` runs `.github/workflows/release.yml`: validate (tag matches `version` in `pyproject.toml`, newest changelog entry is `## [X.Y.Z] - YYYY-MM-DD`), the CI checks (`ci.yml` as a reusable workflow), `uv build` with a smoke test of the wheel (`xlsxpress --version`), publish to PyPI (trusted publishing, environment `pypi`, which allows only `v*` tags), then a GitHub release with the newest changelog entry and the built files. | PyPI comes before the GitHub release because a version can never be uploaded to PyPI again, while a GitHub release can be redone. To release: bump the version and `uv lock`, date the changelog entry, make sure CI is green on `main`, then tag and push. |

## Ideas for later

- Optional decimal-comma parsing (`1,5`) for German-locale exports. Not automatic: `1,234` means 1.234 in German and 1234 in English.
- Perseus matrices: their `#!{Type}` annotation rows below the header make every column text.
- An option to write integers over 15 digits as text.

## Testing approach

- **Unit tests** check one function or class on its own. Keep them focused: main behaviour, documented errors, realistic edge cases. No test for every trivial variation; use `pytest.mark.parametrize` instead of near-duplicate tests.
- **Exception: data conversion.** Reading and writing decide whether values survive, so they're tested thoroughly: every data type, every Excel limit, every decision in the table above.
- **Integration tests** check high-level behaviour across modules: a file goes in, a workbook comes out, CLI and GUI paths give the same result, context-menu registration round trips (Windows only).
- **Bugs:** the test is written first and must fail; the fix follows in the same commit, so the branch never carries failing tests.
- Coverage is reported in CI but isn't a target.

## Working notes

- **Checks.** Every change ends with green checks (ruff, pyrefly, pytest).
- **Test speed.** The whole suite runs in about 2 s. Keep each test well under 1 s; test limits with lowered constants instead of huge inputs.
- **Commits.** Commit this document together with the change it describes.
- **Manual checks.** The test suite doesn't cover the right-click entries, "Show in folder" and the dialog on a second monitor; look at them by hand after changes there.
